# vivo 原子岛 MediaSession 解锁 —— 方案与验证报告

**结论：已达成。** 系统内置原子岛现在可以识别、接受并完整驱动标准原生 Android `MediaSession` 的第三方应用，封面、标题、艺术家、进度条全部正常。全程仅运行时 Hook，未刷写任何分区，未改动 Bootloader。

---

## 1. 目标与硬约束

| 项 | 内容 |
| --- | --- |
| 目标 | 解除原子岛对标准 MediaSession 的白名单限制，让符合原生规范的第三方应用可驱动原子岛 |
| 验证样本 | `com.example.piliplus`（Pili-Plus，标准 `MediaSession` + `tag=media-session`） |
| 修改层级 | **仅运行时 / 内存层**（Xposed Hook） |
| 禁止 | 刷写分区、写入/修改 BL、修改任何系统分区镜像 |
| ADB 工具 | `adb`（1.0.41 / 37.0.0） |

## 3. 原子岛音乐卡片的数据链

```
vivo framework AudioFeatures
  TrackState:pid=;streamType=;playState=;uid=
    └─ com.vivo.musicwidgetmix / MainApplication$m.onCallback()   解析状态
        └─ 闸门②  utils.d.Z(ctx, pkg)                          白名单准入
            └─ MainApplication.g1(pkg, state, delay, size)      派发
                └─ MusicWidgetMixService.k1(pkg)                切源
                    └─ MusicWidgetMixService$j.run()
                        └─ 闸门③  n0(pkg)                       控制器准入
                            └─ controller.d3.a(ctx,type,pkg,cb)  适配器工厂
                                └─ new z2(ctx, pkg, cb)          通用 MediaSession 控制器
                                    └─ z2.a()   -> utils.u.c()   取该包 MediaController
                                        └─ z2.a0() -> 读 MediaMetadata -> 发 what=259
                                            └─ z2.x(259) -> utils.p.s()   封面/标题/进度落地
                                                └─ p.T() -> 卡片 UI

另一条独立准入（island 进程侧）
  闸门①  s4.m0.e() / d() / b() / c()   标准 MediaSession 的可见性白名单
```

### 四道闸门与本模块的处置

| 闸门 | 位置 | 原行为 | 模块处置 |
| --- | --- | --- | --- |
| ① | `s4.m0` 的 `e()/d()/b()/c()` | 返回写死的厂商白名单 | 合并注入目标包（不可变 List 时改为复制后替换） |
| ② | `utils.d.Z(Context,String)` | 白名单判定，false 直接丢弃该 App | 目标包强制 `true`；同时 `W()` 强制 `true`、`Y()` 强制 `false`（黑名单旁路） |
| ③ | `utils.d.e(Context,String)` + `MusicWidgetMixService.n0(String)` | `e()` 是写死的包名白名单，第三方一律 false → `n0()` 返回 true → **跳过控制器创建** | `e()` 目标包强制 `true`；`n0()` 目标包强制 `false` |
| — | `MainApplication$k.onActiveSessionsChanged` | 用 `m0.e()` 做准入 | 由闸门① 覆盖 |

> **闸门③ 是"有岛无封面/进度"的真正根因。** 闸门①② 只让原子岛愿意接受这个 App（岛出现、能控制播放/暂停），但音乐卡片的数据源控制器从未被创建，`MediaMetadata` 自然永远读不到。

## 4. 模块实现

源码：`.\src\com\islandfix\module\IslandFix.java`
作用域：`com.vivo.musicwidgetmix`、`com.vivo.systemuiplugin`

### 功能 Hook

| 目标 | 方法 | 动作 |
| --- | --- | --- |
| `s4.m0` | `e` `d` `b` `c` | 返回值并入目标包 |
| `com.vivo.musicwidgetmix.utils.d` | `Z(Context,String)` | 强制 `true` |
| 同上 | `W(Context,String)` | 强制 `true` |
| 同上 | `Y(Context,String)` | 强制 `false`（黑名单旁路） |
| 同上 | `e(Context,String)` | 强制 `true`（修正"受支持"映射） |
| `MusicWidgetMixService` | `n0(String)` | 强制 `false`（放行控制器创建） |

### 关键开关

```java
private static final String[] TARGET_PKGS = { "com.example.piliplus" };
private static final boolean ALLOW_ALL = true;   // true=任意包放行；false=仅 TARGET_PKGS
private static final boolean PROBE     = false;  // 诊断探针，正式版关闭
```

`ALLOW_ALL=true` 对应"彻底解除白名单"的目标；若只想放行特定 App，改为 `false` 并维护 `TARGET_PKGS`。

### 常驻验证标记（仅目标包打印）

- `controller z2 created for com.example.piliplus` —— 闸门③ 已放行，控制器建成
- `metadata delivered for com.example.piliplus -> title=…, duration=…, cover=bitmap` —— 元数据已交给卡片 UI

### 无 Manager 时直接写 LSPosed 配置库

配置库：`/data/adb/lspd/config/modules_config.db`（SQLite，WAL 模式）

```sql
INSERT OR REPLACE INTO modules_state (module_pkg_name, user_id, enabled, scope_request_blocked)
  VALUES ('com.islandfix.module', 0, 1, 0);

INSERT OR REPLACE INTO scope (module_pkg_name, app_pkg_name, user_id)
  VALUES ('com.islandfix.module', 'com.vivo.musicwidgetmix', 0);

INSERT OR REPLACE INTO scope (module_pkg_name, app_pkg_name, user_id)
  VALUES ('com.islandfix.module', 'com.vivo.systemuiplugin', 0);
```

写入方式（设备自带 `sqlite3`）：

```powershell
& $adb push enable.sql /data/local/tmp/enable.sql
& $adb shell "su -c 'sqlite3 /data/adb/lspd/config/modules_config.db < /data/local/tmp/enable.sql'"
```

`modules` 表由 LSPosed 扫描 APK 的 `xposedmodule` meta-data 自动登记，无需手写。**配置库修改后同样需要软重启**才会被 lspd 重新加载。

## 8. 回滚

模块为纯运行时 Hook，回滚不涉及任何分区。

```powershell
$adb = 'adb'

# 方式 A：仅停用（保留 APK）
#   在 LSPosed 中关闭模块开关；或直接改配置库：
& $adb shell "su -c 'sqlite3 /data/adb/lspd/config/modules_config.db \"UPDATE modules_state SET enabled=0 WHERE module_pkg_name=(SELECT module_pkg_name FROM modules WHERE module_pkg_name LIKE ''com.islandfix.module%'');\"'"
& $adb shell "su -c 'ksud soft-reboot'"

# 方式 B：彻底卸载
& $adb uninstall com.islandfix.module
& $adb shell "su -c 'sqlite3 /data/adb/lspd/config/modules_config.db \"DELETE FROM scope WHERE module_pkg_name LIKE ''com.islandfix.module%''; DELETE FROM modules_state WHERE module_pkg_name LIKE ''com.islandfix.module%''; DELETE FROM modules WHERE module_pkg_name LIKE ''com.islandfix.module%'';\"'"
& $adb shell "su -c 'ksud soft-reboot'"

# 配置库备份（部署时已生成）
& $adb shell "su -c 'cp /data/adb/lspd/config/modules_config.db.bak-islandfix /data/adb/lspd/config/modules_config.db'"
```

卸载后原子岛恢复出厂行为，仅识别 vivo 原生白名单应用。

## 9. 已知边界

- **封面来源**：`utils.p.s()` 依次尝试 `ALBUM_ART` → `DISPLAY_ICON` → `description.iconBitmap` → `ALBUM_ART_URI` / `DISPLAY_ICON_URI`。Pili-Plus 提供了位图（实测 `albumArt=bitmap`），因此有封面。若某应用只提供 URL，走 Glide 异步加载，首帧可能短暂空白。
- **进度条**：依赖 `PlaybackState.position` / `speed` / `duration`。应用不提供 `duration` 时进度条无法计算，这与白名单无关。
- **作用域**：模块只作用于 `com.vivo.musicwidgetmix` 与 `com.vivo.systemuiplugin`，不注入其他进程。
- **兼容性**：Hook 目标为 `PD2352B_A_16.2.17.0.W10` 的类名与签名。系统升级后若 vivo 重新混淆/重构，需按第 3 节的链路重新定位（探针开关 `PROBE=true` 可直接复用）。
- **探针版本**：`out\islandfix-v1.3-probe.apk`（链路定位用，含全量日志）保留备查；正式使用请装 `v1.5-release` / `v1.6-verified`。
